# DECK ORDER IS DATA, NOT FILENAME SORT.
#
# The frames used to be ordered by `ls frames/*.tex | sort`, with \section buried inside
# whichever frame happened to come first in its group.  That made two things impossible:
# moving a frame between sections (its \section moved with it), and holding a frame back
# without deleting it.  Both are needed, because this deck has two audiences.
#
# THE SPINE IS ARCHITECTURAL.  Every term in this work is new to a first-time reader --
# op-class, hop, presence, retime, ring, obligation ledger, Mark, generation, memory token.
# A reader who has not yet been given those words cannot use a frame that debugs them.  So
# the main deck spends its frames DEFINING each concept and saying why it must exist, in the
# WHEN -> WHERE -> HOW order the architecture itself has.
#
# THE APPENDIX IS THE EVIDENCE.  The deep dives, the post-mortems and the per-feature
# matrices are all still here and still built -- they are what a reviewer asks for when they
# challenge a spine claim.  They sit behind \appendix so they do not count against the
# progress bar or the frame numbering.
#
# Syntax:  @section <name>   start a numbered section
#          @appendix         everything after this is backup
#          <basename>        include frames/<basename>.tex
#          # ...             comment
